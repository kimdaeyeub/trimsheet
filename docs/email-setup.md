# 새 데이터 이메일 알림 설정

에이전트가 가격표를 정리해 Google Sheets에 새 차종 데이터를 추가하면, 화면의 **이메일 알림**에 등록한 주소로 메일을 보냅니다. 발송은 Cloudflare Email Service(Workers `send_email` 바인딩)를 씁니다.

설정을 마치기 전에도 주소 등록은 됩니다. 주소는 시트에 저장되고, 발송만 하지 않습니다. 이때 화면에 노란 안내가 보입니다.

## 비용과 플랜

| 받는 주소 | 필요한 플랜 | 비용 |
| --- | --- | --- |
| Cloudflare에서 **인증한 주소**(Email Routing의 받는 주소) | Workers 무료 | 무료 |
| 아무 주소 | Workers 유료(Paid) | Workers 유료 플랜 요금 + Email Sending 사용량 |

개인용이면 **본인 주소를 인증해서 무료로 쓰는 것**을 권장합니다. 인증하지 않은 주소는 무료 플랜에서 발송이 실패하고, 실패는 로그에만 남습니다. 작업 자체는 실패하지 않습니다.

## 1. 보내는 도메인 준비 (한 번만)

Cloudflare에 연결된 도메인이 있어야 합니다. 보내는 주소는 그 도메인의 주소여야 합니다(예: `trimsheet@내도메인.com`).

1. Cloudflare 대시보드 → **Compute & AI → Email Service** → **Onboard Domain** → 도메인 선택
2. 안내에 따라 SPF·DKIM DNS 레코드를 추가합니다. Cloudflare DNS를 쓰면 보통 5~15분 걸립니다.

## 2. 받는 주소 인증 (무료 플랜일 때)

1. 대시보드 → **Email Service → Email Routing → Destination addresses** → 받을 주소 추가
2. 그 주소로 온 인증 메일의 링크를 누릅니다.

## 3. 백엔드 설정

`backend/wrangler.jsonc`에는 이미 `send_email` 바인딩(`EMAIL`)이 들어 있습니다. 값 두 개만 넣으면 됩니다.

| 값 | 설명 |
| --- | --- |
| `NOTIFY_FROM` | 보내는 주소. 1번에서 준비한 도메인의 주소 |
| `APP_URL` | 선택. 메일 속 "차종 정보 보기" 버튼이 여는 앱 주소(배포한 프론트엔드 URL) |

- **로컬:** `backend/.env`에 넣고 백엔드 dev 서버를 다시 시작합니다.
- **배포:** 아래처럼 비밀값으로 등록합니다.

```bash
cd backend && npx wrangler secret put NOTIFY_FROM
```

```bash
cd backend && npx wrangler secret put APP_URL
```

공개 저장소라 도메인과 주소는 설정 파일에 넣지 않습니다.

## 4. 확인

1. 화면 오른쪽 위 **이메일 알림** → 주소 등록
2. 같은 창의 **테스트 메일 보내기** → 결과 문구 확인

로컬 개발(`npm run dev`)에서는 바인딩이 **흉내만 내고 실제로 보내지 않습니다**. 메일 내용은 백엔드 터미널 로그에 찍힙니다. 실제 발송은 배포한 뒤 확인하세요. 로컬에서 실제로 보내려면 `wrangler.jsonc`의 바인딩에 `"remote": true`를 잠시 넣으면 됩니다.

## 동작 방식

- **저장 위치:** 주소는 Google Sheets 숨김 탭 `_설정`의 `notify.emails` 키에 저장됩니다. DB는 쓰지 않습니다.
- **화면 표시:** 화면에는 주소 일부만 보입니다(`ja******@example.com`). 전체 주소는 브라우저로 보내지 않습니다.
- **보내는 시점:** `finalize_job`이 시트에 결과를 쓴 직후 보냅니다. 별도 단계로 분리해 두어서, 시트 쓰기를 다시 시도해도 메일이 두 번 가지 않습니다.
- **받는 사람:** 주소마다 따로 보내서, 받는 사람끼리 서로의 주소를 볼 수 없습니다. 최대 20개까지 등록할 수 있습니다.
- **보내지 않는 경우:** 첫 스캔(기준선 등록)처럼 데이터가 추가되지 않으면 보내지 않습니다.
